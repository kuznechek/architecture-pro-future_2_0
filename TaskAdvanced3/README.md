## Ключевые блоки целевой архитектуры

| Компонент | Технологии | Назначение |
|-----------|------------|-------------|
| API Gateway | Kong / Envoy | Единая точка входа для всех внешних систем, аутентификация, маршрутизация, rate limiting |
| Event Bus | Apache Kafka | Приём событий от доменов (клиники, финтех, ИИ), обеспечение асинхронного обмена |
| Обработка данных | Apache Flink, Spark | Потоковая и пакетная обработка, трансформация данных, расчёт витрин |
| Data Lakehouse | Apache Iceberg + S3 | Единое хранилище сырых и агрегированных данных с поддержкой ACID и time travel |
| Data Catalog & Governance | Open Metadata / DataHub | Управление метаданными, поиск данных, lineage, политики доступа |
| Self-Service BI | Superset / Power BI | Построение отчётов и дашбордов конечными пользователями |
| IAM & Security | Keycloak + OPA | Централизованное управление доступом, разграничение по ролям и атрибутам данных |
| Observability | Prometheus + Grafana + ELK | Сбор метрик, логов, трассировка для всех сервисов |

## Карта рисков трансформации

| Риск | Вероятность | Влияние | Меры снижения |
|------|-------------|---------|----------------|
| Рост затрат на облачные ресурсы | Средняя | Высокое | Мониторинг, автоматическое управление хранилищем |
| Утечка медицинских/финансовых данных | Низкая | Критическое | Шифрование, IAM, аудит, маскирование данных |
| Интеграция устаревших систем (PowerBuilder, SQL Server 2008) | Высокая | Среднее | Поэтапная миграция, CDC-коннекторы |
| Сопротивление переходу на новые BI-инструменты | Средняя | Низкое | Обучение, пилоты, центр компетенций |
| Нехватка экспертизы в команде | Высокая | Среднее | Найм экспертов, курсы, наставничество |
| Задержки внедрения из-за сложности оркестрации | Низкая | Среднее | IaC, CI/CD, автоматизация тестов |

## План управления рисками

### 1. Рост затрат на облачные ресурсы
- Вероятность: средняя  
- Влияние: высокое  
- Тип меры: технический  
- Меры снижения:  
  - Настроить автоматическое перемещение старых данных в холодное хранилище  
  - Внедрить дашборды мониторинга затрат и алерты при превышении бюджета  

### 2. Утечка медицинских или финансовых данных
- Вероятность: низкая  
- Влияние: критическое  
- Тип меры: технический и управленческий  
- Меры снижения:  
  - Шифровать данные в покое и при передаче  
  - Внедрить контроль доступа на уровне строк  
  - Вести аудит всех запросов  
  - Проводить регулярные пентесты  
  - Подписывать соглашения о неразглашении  
  - Обучать персонал правилам работы с данными  

### 3. Интеграция устаревших систем (PowerBuilder, SQL Server 2008)
- Вероятность: высокая  
- Влияние: среднее  
- Тип меры: технический  
- Меры снижения:  
  - Использовать CDC-коннекторы (Debezium) для выгрузки изменений из SQL Server в Kafka  
  - Поэтапно переносить бизнес-логику из PowerBuilder в микросервисы  

### 4. Сопротивление переходу на новые BI-инструменты
- Вероятность: средняя  
- Влияние: низкое  
- Тип меры: управленческий  
- Меры снижения:  
  - Провести обучение и демонстрации преимуществ  
  - Создать центр компетенций для поддержки пользователей  
  - Переводить отчёты постепенно, сохраняя доступ к старым инструментам  

### 5. Нехватка экспертизы в команде
- Вероятность: высокая  
- Влияние: среднее  
- Тип меры: управленческий  
- Меры снижения:  
  - Нанять внешних экспертов на первые месяцы  
  - Оплатить курсы и сертификации команды  
  - Организовать внутренние воркшопы и наставничество  

### 6. Задержки внедрения из-за сложности оркестрации
- Вероятность: низкая  
- Влияние: среднее  
- Тип меры: технический  
- Меры снижения:  
  - Внедрить Infrastructure as Code (Terraform) и GitOps (ArgoCD)  
  - Автоматизировать тестирование пайплайнов (validate, plan, apply)
